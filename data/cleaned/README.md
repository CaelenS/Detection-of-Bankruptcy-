# Cleaned bankruptcy datasets

Generated by `data_cleaning.ipynb` from the five original ARFF files in `data/raw/`.
Run the notebook from the repository root, in cell order.

Exact duplicate full rows were removed, keeping the first occurrence. This treats identical records as redundant; company identities are not available in these files.
Each year is split separately into approximately 70% training, 15% validation, and 15% test, stratified by bankruptcy class with seed 42.
Missing features are filled using only that year's training medians. Targets and observed values are unchanged. There is no scaling, clipping, resampling, or model fitting.

Each split CSV has 64 features plus `bankrupt`. The companion row-ID CSV preserves zero-based original row positions in matching order; do not use those IDs as model features.
Training medians, summary tables, original-file hashes, and software versions are included for reproducibility.
Regenerating the notebook overwrites these derived files, not the raw ARFF files.

These splits do not establish independence between companies across year files or chronological performance. Do not pool these files without reviewing that limitation.
All model comparison should use these same splits; the earlier exploratory modeling notebook used different splits and is not a comparable result.

## File numbers and prediction horizons

UCI describes the file numbers as years within the forecasting period, not years ahead.

| File | Years ahead |
|---|---:|
| 1year.arff | 5 |
| 2year.arff | 4 |
| 3year.arff | 3 |
| 4year.arff | 2 |
| 5year.arff | 1 |

Source: https://archive.ics.uci.edu/dataset/365/polish+companies+bankruptcy+data (Additional Information).
Export filenames retain the original file numbers. This correction changes labels, not data or split membership.

## Folder layout

- `1year/` through `5year/`: each contains its training, validation, and test CSVs. Folder numbers follow the original filenames, not years ahead.
- `supporting_records/`: original row IDs, training medians, summary tables, and cleaning metadata. These document the cleaning; they are not additional model datasets.

Example: `1year/1year_train.csv` contains the cleaned training data from `1year.arff` (five years ahead).
